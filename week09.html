The last line must print new model ok. --force-reinstall removes last week's version first; --no-deps leaves GDAL and the other packages exactly as they are. If the download fails, open the repository page, choose Code → Download ZIP, and give pip that file instead (don't unzip it).

02 Atlanta on your site

From now on we work on Atlanta. I downsampled the data and put it on Dropbox. SmallSample_800px holds nine tiles of 800 × 800 px around campus, plus tiles_index.csv. The Georgia Tech campus is the middle one, r1c1_C:

Where it goes

  1. Empty cool-choices/backend/scene/ (the Austin rasters and ownmet_Forcing_data.txt; keep a copy somewhere else if you like) and copy the files of r1c1_C into it.
  2. In backend/app/model.py, change three things:
    • MET: the name of the Atlanta weather file.
    • DATE: the date in that file. The first two numbers of every row are the year and the day of the year.
    • tile_size=600 → tile_size=1000. The model cuts anything bigger than tile_size into several tiles, and your site only shows the first one (0_0). At 800 × 800 px, 600 is too small.
  3. In backend/: python -m app.baseline --force (without --force it keeps the Austin baseline), then restart uvicorn and reload the page.

No coordinates to change: the backend reads where the tile is from the rasters themselves, so the outline, the overlay and the map's starting point move to Atlanta on their own. The tile is bigger than the Austin subset, though, so if it doesn't fit on screen, lower zoom: 15.2 in MapArea.jsx (try 14.5).

How many hours?

Count the rows in the weather file. The site assumes 24 hours: the slider (0–23) in Panel.jsx, the play loop in App.jsx and timesteps_total in jobs.py. If the file has fewer, those have to follow the real number (the run's result.json lists the hours).

04 Run SOLWEIG-Lite on a tile

This one is for the last feature, the city-wide prototype: every tile of the city will need its baseline computed ahead of time, by a script like the one you write here. This time you run SOLWEIG-Lite directly from Python, outside the website. One tile is enough for this week.

Step 1 · Pick a tile and look at it

Download the whole SmallSample_800px folder and pick any tile except r1c1_C (that one is already on your site). Inside: four rasters and one weather file. Open the weather file in a text editor. Each row is one hour, and the first two numbers are the year and the day of the year. Which date is it? Write it down; you'll need it in step 3.

Step 2 · Find the weather file

Make a new file, run_tile.py, anywhere outside cool-choices (for example in Documents/week09/), and start from this. The run() function, the part you can't guess, is done; the TODOs are yours. Set SAMPLE and TILE_NAME first.

Write find_met(tile): it gets the tile folder and returns the path of its weather file. Hints:

  • tile is a Path. tile.glob("*.txt") finds every .txt file in it, and next(...) takes the first one. There is only one.
  • Or loop over tile.iterdir() and keep the file whose .suffix is ".txt".

Test as you go: put a # in front of the run(...) line for now, and run python run_tile.py. The print line shows what your functions return.

Step 3 · Read the date

Write date_of(met): it returns the date of the weather file as text, like "2023-06-25". The model needs it to get the time zone right. Hints:

  • with open(met) as f: opens the file, and f.readline() reads one line. The first line is the header; the second is the first hour.
  • .split() turns a line into a list of words; int(...) turns a word into a number.
  • import datetime, then datetime.date(year, 1, 1) + datetime.timedelta(days=day - 1) is day number day of that year, and .isoformat() writes it as "YYYY-MM-DD".

Does it print the same date you found in step 1?

Step 4 · Run it, and time it

Remove the # in front of run(...) and run the script. Then print how many seconds the run takes: import time, and time.perf_counter() gives the current time in seconds, so call it just before and just after run(...). The very first run is slower, because the model compiles itself once.

Step 5 · Look at the result

The results are in the tile's output_folder/0_0/: TMRT_0_0.tif and UTCI_0_0.tif, one band per hour. Print the mean TMRT of every hour. Hints:

  • from osgeo import gdal, and call gdal.UseExceptions() once (otherwise GDAL prints a warning).
  • gdal.Open(str(path)).ReadAsArray() gives a NumPy array shaped (hours, rows, columns).
  • A for loop over that array gives one hour at a time (enumerate adds the number), and numpy.nanmean() averages it, skipping empty pixels.
