The last line must print new model ok. --force-reinstall removes last week's version first; --no-deps leaves GDAL and the other packages exactly as they are. If the download fails, open the repository page, choose Code → Download ZIP, and give pip that file instead (don't unzip it).

02 Atlanta on your site

From now on we work on Atlanta. I downsampled the data and put it on Dropbox. SmallSample_800px holds nine tiles of 800 × 800 px around campus, plus tiles_index.csv. The Georgia Tech campus is the middle one, r1c1_C:

Where it goes

  1. Empty cool-choices/backend/scene/ (the Austin rasters and ownmet_Forcing_data.txt; keep a copy somewhere else if you like) and copy the files of r1c1_C into it.
  2. In backend/app/model.py, change three things:
    • MET: the name of the Atlanta weather file.
    • DATE: the date in that file. The first two numbers of every row are the year and the day of the year.
    • tile_size=600 → tile_size=1000. The model cuts anything bigger than tile_size into several tiles, and your site only shows the first one (0_0). At 800 × 800 px, 600 is too small.
  3. In backend/: python -m app.baseline --force (without --force it keeps the Austin baseline), then restart uvicorn and reload the page.

No coordinates to change: the backend reads where the tile is from the rasters themselves, so the outline, the overlay and the map's starting point move to Atlanta on their own. The tile is bigger than the Austin subset, though, so if it doesn't fit on screen, lower zoom: 15.2 in MapArea.jsx (try 14.5).

How many hours?

Count the rows in the weather file. The site assumes 24 hours: the slider (0–23) in Panel.jsx, the play loop in App.jsx and timesteps_total in jobs.py. If the file has fewer, those have to follow the real number (the run's result.json lists the hours).

04 Run SOLWEIG-Lite on a tile

This one is for the last feature, the city-wide prototype: every tile of the city will need its baseline computed ahead of time, by code like the one you write here. This time you run SOLWEIG-Lite directly from Python, outside the website, in a Jupyter notebook. One tile is enough for this week.

Get the notebook and open it

Download week09_run_tile.ipynb from the same Dropbox folder, together with the whole SmallSample_800px folder, and put the notebook in a folder of its own, for example Documents/week09/. Then install Jupyter into your solweig-light environment (once) and start it from there:

Your browser opens; double-click week09_run_tile.ipynb on the left. Start Jupyter from the activated solweig-light environment like this; otherwise the notebook can't find SOLWEIG-Lite. (If you use VS Code, you can open the notebook there instead and pick solweig-light as the kernel.)

Never used Jupyter?

A notebook is a list of cells: text cells and code cells. Click a code cell and press Shift+Enter to run it and move to the next one (Ctrl+Enter, or Cmd+Enter on a Mac, runs it and stays). Run the cells from top to bottom. [*] next to a cell means it's still running. If things get weird, Kernel → Restart Kernel and run from the top again. If it still doesn't make sense, send me a Teams message!

The steps

The notebook walks you through these. The model call itself is written for you; the parts marked TODO are yours, with hints right above each one.

  1. Pick a tile and look at it. Any tile except r1c1_C (that one is already on your site). Open its weather file and find the date by hand.
  2. Find the weather file. Write a small function that finds the .txt file in a tile folder.
  3. Read the date. Write a function that reads the date from the weather file, and check it against the one you found by hand.
  4. Run SOLWEIG-Lite, and time it. Run the model on your tile and print how many seconds it took.
  5. Look at the result. Open the TMRT output and print the mean TMRT of every hour. When is it hottest?

There's also an optional extra at the end: draw the TMRT map of the hottest hour.
