Rebuild Week 1's layout as three independent pieces, each in its own file, and learn the one mechanism that moves data between them.

By the end of this week you will

  • Have a running React project created with Vite
  • Know what a component is and why the page is split into three of them
  • Read and write JSX without fighting it
  • Pass a value from a parent component into a child

01 Why React at all

Your Week 1 page is fixed. Nothing on it ever changes. The application you are building is the opposite: markers appear when clicked, a list grows and shrinks, results arrive from a server and get drawn.

You could do all of that by hand — find an element, create another one, insert it, remember to remove it later. That works for ten lines and becomes unmanageable at a hundred, because you end up tracking what is currently on screen as well as what should be.

React removes the second job. You describe what the page should look like for the current data, and React works out what to change on screen. Add an item to a list and the list redraws itself. You never touch the page directly again.

A component is one reusable piece of that description: a function that returns some markup. Your page becomes three of them, and each can be opened, understood, and fixed on its own.

04 Four JSX rules

React components return something that looks like HTML but is written inside JavaScript. It is called JSX, and it follows four rules that catch everyone once.

1 · class becomes className

class is a reserved word in JavaScript, so JSX uses a different name for the same thing. This is the single most common JSX mistake, and the most annoying, because nothing breaks — your styles simply do not apply.

2 · Every tag closes

HTML tolerates <br> and <img> left open. JSX does not.

3 · One outer element

A component returns exactly one thing. If you need two side by side, wrap them — either in a real element or in an empty pair of brackets when you do not want an extra div.

4 · Curly braces escape back into JavaScript

Inside JSX, { } means "stop writing markup, evaluate this expression, and put the result here".

07 When it breaks

The page is completely blank and white

A JavaScript error stopped React before it drew anything. Press F12 and read the Console tab — the first red message names the file and line. A blank page always has an explanation waiting there.

Failed to resolve import "./components/Sidebar"

The path or the filename does not match. Check the spelling and the capital letter — sidebar.jsx and Sidebar.jsx are different files on the servers you deploy to in Week 12, even if your own computer is relaxed about it. Also confirm the file is in src/components/ and not in src/.

My styles are not applying

You wrote class instead of className. React ignores class without complaining. Search your components for class= and fix each one.

Everything is squashed into a strip at the top

html, body, #root { height: 100%; } is missing from index.css. See the warning in step 5 — this one is specific to React and did not exist in Week 1.

Adjacent JSX elements must be wrapped in an enclosing tag

Your component returns two things at the top level. Wrap them in a single element, or in <> and </> if you do not want an extra div in the output.

The Vite welcome page is still showing

App.jsx was not saved, or you edited a different App.jsx than the one being served. Confirm the file path is frontend/src/App.jsx, and check the terminal running npm run dev for errors it may be printing.

Port 5173 is already in use

An earlier npm run dev is still running in a terminal you closed the window on. Vite will usually offer the next port instead, which is fine. To reclaim 5173, find and stop the old process — or simply restart your computer, which is faster than looking it up.
