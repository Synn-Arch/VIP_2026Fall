JavaScript: four essential patterns

Almost every line of frontend code you write this semester is one of four moves. Learn those four properly and skip the rest of the language for now.

≈2 hours 5 exercises, self-marking No React yet

By the end of this week you will

  • Store a list of things as an array of objects — the shape all your data takes
  • Add and remove items without modifying the original array
  • Run code in response to a click
  • Wait for something slow to finish, using async and await
What is deliberately missing

Classes, prototypes, closures, inheritance, modules, this. These are real parts of JavaScript and you will meet them eventually. You will not need any of them in this course, and learning them now costs you the time you need for the four patterns that matter.

01 Where JavaScript runs

The same language runs in two places, and this week you use both.

In the browser, where it can change what is on the page. Press F12 on any web page and pick the Console tab — you can type JavaScript there and see it run immediately. It is the fastest way to test one line.

In your terminal, through Node — the thing you installed last week. This runs a file top to bottom with no page involved, and it is how you will check your exercises:

Same language, same rules. The only difference is what is available around it: the browser has a page, Node has your file system.

03 Pattern 2 · Changing without changing

This is the pattern that trips people up, and it is worth slowing down for. From Week 4, React only redraws the screen when it notices that your data was replaced. If you modify an array in place, React sees the same array it already had and nothing happens on screen — your code is correct and the page is frozen.

So the rule is: never change an array. Build a new one.

Two equals signs or three?

Always three. === compares value and type strictly. == performs conversions behind your back — "1" == 1 is true — and produces bugs that are genuinely hard to find. Use === and !== without exception.

04 Pattern 3 · Events

An event is something that happened — a click, a keystroke, a drag. You respond by handing over a function to be called when it happens.

Notice what you are not doing: you never call that function yourself. You give it away and the browser calls it later, possibly many times, possibly never. That inversion is the whole idea, and it is exactly how React works too — in Week 4 you will write onClick={handleAdd}, which is the same move in different clothing.

The event argument carries details about what happened. You will not need much from it until Week 6, when a map click hands you the coordinates you clicked at.

console.log is your main debugging tool

When something does not behave, print the value and look at it. Most bugs in this course are not broken logic — they are a value being a different shape than you assumed. console.log(placements) answers that question in one second.

05 Pattern 4 · Waiting for slow things

Asking a server for something takes time — maybe 50 milliseconds, maybe two seconds. JavaScript refuses to freeze while it waits, so slow operations hand back a Promise: a receipt that says "an answer will exist here later".

await pauses your function until that receipt is honoured. Any function containing await must be marked async:

07 When it breaks

Cannot find module 'practice.js'

Your terminal is in a different folder than the file. Run ls (or dir on Windows) to see what is around you — if practice.js is not in that list, use cd spatial-app to move into the right folder and try again.

Every check prints received undefined

The function has no return. A JavaScript function that does not explicitly return something returns undefined. Calculating the answer is not enough — you have to hand it back.

Check 2 or 3 passes but "left the original alone" fails

You modified list instead of building a new array. push, splice, sort, and reverse all change the array they are called on. Use [...list, item] to add and list.filter(...) to remove — both return something new and leave the original as it was.

Check 5 returns a Promise instead of 3

The await is missing. Without it you are returning the receipt rather than the thing the receipt was for. Write const data = await fakeServer(); and then return data.count.

SyntaxError: Unexpected token

A bracket, brace, or quote is unbalanced. The error message names a line number — the real problem is usually on that line or the one just above it. In VS Code, clicking next to a bracket highlights its partner, which finds the gap quickly.

My arrow function returns nothing

(p) => p.type returns p.type, but (p) => { p.type } returns undefined. Adding braces turns the arrow into a normal function body, which then needs an explicit return. Either drop the braces or write return inside them.
