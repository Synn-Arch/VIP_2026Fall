Week 5 · Feb 17 – Feb 24

Rendering a Mapbox map

Replace the gray placeholder with a real, interactive, zoomable map — and learn how to keep a secret out of your source code while doing it.

Milestone 1 ≈2 hours Free Mapbox account required

By the end of this week you will

  • Have a Mapbox account and a public access token
  • Keep that token in an environment file, out of your repository
  • Have a live map filling the center of your application
  • Have one marker drawn at a coordinate you chose

01 Get a token

Mapbox draws the map, and it needs to know who is asking. That identification is a token — a long string beginning with pk. that your application sends with every request for map tiles.

Sign up for a free account at account.mapbox.com. Once you are in, the account page shows a default public token. Copy it.

Public token only

Mapbox issues two kinds. Public tokens begin with pk. and are meant to be sent to browsers — that is the one you want. Secret tokens begin with sk. and must never appear in frontend code, because anything the browser receives can be read by anyone. If you ever create a token yourself, check the first two characters.

Do not paste your token into a chat message, a shared document, or a screenshot without blurring it. In Week 12 you will lock it to your own domain; until then, treat it as a password.

Why an environment file

A secret in your source code is a secret in your repository, and a repository is public and permanent. An environment file keeps the value beside the code without being part of it, which also means each person and each server can hold a different value. Two packages, because they do different jobs. mapbox-gl is the map engine itself — it knows nothing about React. react-map-gl is a thin wrapper that lets you write the map as JSX components alongside the rest of your interface.

Restart the dev server after touching .env

Vite reads environment files once, at startup. Create or edit .env while the server is running and it will not notice. Every time you change that file: Ctrl+C, then npm run dev again. Skipping this produces a token that is undefined for no apparent reason.

What each prop does

  • mapboxAccessToken — your identification, read from the environment file
  • initialViewState — where the map sits when it first appears. Initial is literal: after this, the user is in charge, and changing these numbers will not move a map that is already on screen unless you reload
  • style — the size of the map element on the page, in CSS terms
  • mapStyle — which cartography to draw. Mapbox provides several; streets-v12 is a sensible default and light-v11 is a good choice if your analysis colors need to stand out later

Set the longitude and latitude to somewhere relevant to your study area rather than leaving the example values. You can read coordinates off any point in Google Maps by right-clicking it — but note that Google shows them latitude first, which is the reverse of what Mapbox wants.

Nearly every failure this week is one of these. Check them in order before investigating anything else.

1 · The missing CSS import

2 · The VITE_ prefix

Vite only exposes environment variables whose names start with VITE_. This is a safety feature — it stops server secrets from leaking into browser code by accident. Name your variable MAPBOX_TOKEN and it will silently be undefined, with no warning of any kind. To check what actually arrived:

If that prints undefined: the prefix is wrong, the file is in the wrong folder, or you have not restarted the dev server.

3 · Committing .env

If you created the file before adding the ignore line, Git may already be tracking it. Run git status and look. Removing a secret from a repository's history properly is genuinely difficult, so the reliable fix is to delete that token in your Mapbox account and generate a new one.

06 Add a marker

One hard-coded marker, to prove that things can be drawn on top of the map. Next week it becomes one marker per placement, positioned by your clicks.

The marker goes inside the <Map> element, which is why the tag is no longer self-closing. Anything drawn on the map is a child of it.

Longitude comes first

Mapbox writes coordinates as longitude, then latitude. Leaflet — the library most introductory mapping tutorials use — writes them the other way round, as [lat, lng]. Copy a coordinate pair from a Leaflet example without swapping it and your marker lands in the ocean, usually thousands of kilometres from where you meant.

This is the single most common error in the mapping half of this course, and it is the first thing to suspect whenever something appears somewhere absurd. Your data uses named fields — lng and lat — precisely so the order cannot be confused once the value is stored.

08 When it breaks

The map area is blank or plain white

Almost always the token. Open the console with F12 — an unauthorized or 401 error means Mapbox rejected it. Log import.meta.env.VITE_MAPBOX_TOKEN: if it is undefined, see the VITE_ prefix section above; if it prints a token, copy a fresh one from your Mapbox account in case it was truncated when pasted.

The map renders as broken, overlapping fragments

The stylesheet import is missing. Add import "mapbox-gl/dist/mapbox-gl.css"; as the first line of MapArea.jsx.

Failed to resolve import "react-map-gl/mapbox"

You have an older version of the library, where the import path had no suffix. Either change the line to import Map, { Marker } from "react-map-gl";, or install the current version with npm install react-map-gl@latest mapbox-gl and keep the path as written.

The token is undefined even though .env looks right

Three candidates, in order of likelihood. The dev server was not restarted after the file was created. The variable is not prefixed with VITE_. Or the file is in the wrong folder — it belongs beside package.json in frontend, not inside src and not at the top of spatial-app.

The map is a small square instead of filling the area

.map-area still has display: grid and place-items: center from Week 1. Replace that rule with the version in step 4.

The marker is not where I put it

Longitude and latitude are swapped. In most of the world lat is a smaller number than lng, so a quick glance at which value is larger often catches it. Verify the point in Google Maps, remembering that Google prints latitude first and Mapbox wants longitude first.

.env shows up in git status

The ignore rule is not taking effect. Confirm the line is in frontend/.gitignore and is exactly .env. If the file was committed before the rule existed, run git rm --cached .env, commit that, and then generate a replacement token — assume the old one is compromised.
