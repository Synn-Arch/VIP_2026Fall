01 Why React

A plain HTML page is fixed. Nothing on it changes. What you are building is the opposite: markers appear when clicked, a list grows and shrinks, results arrive from a server and get drawn.

You could do that by hand — find an element, create another, insert it, remember to remove it later. That works for ten lines and becomes unmanageable at a hundred, because you end up tracking what is currently on screen as well as what should be.

React removes the second job. You describe what the page should look like for the current data, and React works out what to change on screen. Add an item to an array and the list redraws itself. You never touch the page directly again.

A component is one reusable piece of that description: a function that returns some markup. Your page becomes three of them, and each can be opened and understood on its own.

03 Reading JSX

React components return something that looks like HTML but is written inside JavaScript. It is called JSX, and four rules catch everyone once.

1 · class becomes className

class is a reserved word in JavaScript. This is the most annoying JSX mistake because nothing breaks — your styles simply do not apply.

2 · Every tag closes

3 · One outer element

A component returns exactly one thing. If you need two side by side, wrap them — in a real element, or in <> and </> when you do not want an extra div.

4 · Curly braces escape back into JavaScript

Inside JSX, { } means "stop writing markup, evaluate this, put the result here".

05 Props

Right now Sidebar has its heading baked in. A parent should decide that. Values passed from parent to child are called props, written like HTML attributes.

Change the string in App.jsx and the heading follows. That is all props are — but it is the only mechanism by which data reaches a component, so everything from here runs on it.

Props always flow from parent to child. A child can never reach up and change its parent's data directly, which is exactly what makes a React application possible to reason about.

06 State and lists

State is data that changes while the page is open. Which component type is selected. What has been placed so far. useState hands you two things: the current value, and a function that replaces it.

Two rules, and both of them bite.

Never assign directly

Assigning changes a variable that is about to be thrown away. Only the setter tells React something is different.

The setter replaces — it does not merge

The bug that wastes an hour

placements.push(newOne) followed by setPlacements(placements) does nothing visible. The array now holds the new item, but it is the same array object React already had, so React concludes nothing changed and does not redraw. Your data is right and your screen is stale.

Who holds the data

Both pieces of state go in App, not in Sidebar. That looks like extra work now, but in a moment MapArea needs the same list to draw markers, and later ResultPanel needs it to send to the server. A component cannot reach into a sibling; the only place all three can see is their shared parent.

Data flows down as props. To send something back up, the parent passes down a function and the child calls it.

07 Get a Mapbox token

Mapbox draws the map and needs to know who is asking. That identification is a token — a long string beginning with pk. sent with every request for map tiles.

Sign up free at account.mapbox.com. Your account page shows a default public token. Copy it.

Public token only

Public tokens begin with pk. and are meant to be sent to browsers. Secret tokens begin with sk. and must never appear in frontend code, because anything the browser receives can be read by anyone.

Do not paste your token into a chat message, a shared document, or an unblurred screenshot. Treat it as a password.

What each prop does

  • mapboxAccessToken — your identification, read from the environment file
  • initialViewState — where the map sits when it first appears. Initial is literal: after that the user is in charge, and changing these numbers will not move a map already on screen
  • style — the size of the map element on the page, in CSS terms
  • mapStyle — which cartography to draw. light-v11 is chosen deliberately: your analysis results will be drawn on top in colour later, and a quiet base map lets them read

Three things that break

Nearly every failure here is one of these. Check them in order.

  1. The missing CSS import. Without the first line the map still loads, but renders as broken misaligned fragments with controls in the wrong places. It looks catastrophic and is one line.
  2. The VITE_ prefix. Vite only exposes variables whose names start with VITE_ — a safety feature that stops server secrets leaking into browser code. Name it MAPBOX_TOKEN and it is silently undefined. Check with console.log(import.meta.env.VITE_MAPBOX_TOKEN).
  3. Committing .env. If you created the file before adding the ignore line, Git may already be tracking it. Removing a secret from history properly is difficult, so the reliable fix is to delete that token in your Mapbox account and generate a new one.

09 Markers from your state

This is where the three halves of the week meet. The list in your sidebar and the markers on the map are about to become two views of one array.

Markers go inside the <Map> element, which is why the tag is no longer self-closing. Anything drawn on the map is a child of it.

Now press Add a few times. A marker appears on campus for each one. Delete an item with × and its marker vanishes. You never wrote code to add or remove a marker — you changed an array, and both the sidebar and the map followed. That is the whole idea of React, and it is worth pausing on for a second.

Longitude comes first

Mapbox writes coordinates as longitude, then latitude. Leaflet — the library most introductory mapping tutorials use — writes them the other way round, as [lat, lng]. Copy a pair from a Leaflet example without swapping it and your marker lands in the ocean.

This is why the placement object uses named fields, lng and lat, rather than a two-element array. Once the value is stored the order cannot be confused.

10 When it breaks

The page is completely blank and white

A JavaScript error stopped React before it drew anything. Press F12 and read the Console tab — the first red message names the file and line. A blank page always has an explanation waiting there.

Failed to resolve import "./components/Sidebar"

The path or filename does not match. Check spelling and the capital letter — sidebar.jsx and Sidebar.jsx are different files on the servers you will deploy to, even if your own computer is relaxed about it. Confirm the file is in src/components/, not src/.

My styles are not applying

You wrote class instead of className. React ignores class without complaining. Search your components for class=.

Adjacent JSX elements must be wrapped in an enclosing tag

A component returns two things at the top level. Wrap them in a single element, or in <> and </>.

Clicking Add does nothing

Either you mutated the array instead of replacing it, or onAdd is not reaching the button. Put console.log("add") as the first line of addPlacement: if it prints, the click is fine and the problem is the update; if not, the prop is not wired up.

The tab freezes as soon as items appear

You wrote onClick={onRemove(p.id)} without the arrow. That calls the function during rendering, which changes state, which triggers another render, forever. Add () => in front.

Warning: Each child in a list should have a unique "key" prop

A map is producing elements without key. All three maps need one — key={type} on the palette buttons, key={p.id} on the list items and on the markers.

The map area is blank or plain white

Almost always the token. Open the console — an unauthorized or 401 error means Mapbox rejected it. Log import.meta.env.VITE_MAPBOX_TOKEN: if it is undefined, see the VITE_ prefix note; if it prints a token, copy a fresh one in case it was truncated when pasted.

The map renders as broken, overlapping fragments

The stylesheet import is missing. Add import "mapbox-gl/dist/mapbox-gl.css"; as the first line of MapArea.jsx.

Failed to resolve import "react-map-gl/mapbox"

You have an older version of the library, where the import path had no suffix. Either change the line to import Map, { Marker } from "react-map-gl";, or install the current version with npm install react-map-gl@latest mapbox-gl.

The token is undefined even though .env looks right

Three candidates, in order of likelihood. The dev server was not restarted after the file was created. The variable is not prefixed with VITE_. Or the file is in the wrong folder — it belongs beside package.json, not inside src.

Markers do not appear, or they all sit on top of each other

If none appear, placements is not reaching MapArea — check that App.jsx passes it and that MapArea receives it in its parameter braces. If they stack in one spot, your addPlacement is using fixed coordinates rather than the random offset.

Port 5173 is already in use

An earlier npm run dev is still running in a terminal you closed the window on. Vite will usually offer the next port, which is fine.
