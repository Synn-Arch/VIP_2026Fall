01 What the model does

Stand on the same street at the same moment. A thermometer reads the same air temperature under a street tree and in the middle of an asphalt plaza. The person standing in each place is not experiencing the same heat at all.

The difference is radiation — direct sunlight, shortwave bounced off pavement and walls, and longwave emitted by surfaces that have been baking all afternoon. SOLWEIG collapses all of it into one number, the mean radiant temperature (Tmrt), and computes it for every grid cell on the ground.

So the model is not a map of air temperature. It is a map of what urban form does to the heat a body absorbs. Its inputs are shape — building heights, tree canopy, terrain — and its output is pedestrian-level thermal load.

Add air temperature, humidity, and wind and you get the comfort indices UTCI and WBGT. Tmrt is sharply sensitive to form, so its maps look crisp; UTCI mixes in meteorology and varies more smoothly across space.

This week you get the machinery in place, learn the file structure, and run the model once on a small piece of the sample city so you have real output to look at.

04 Install Miniconda

If you already installed conda or miniconda, you can skip this step.

SOLWEIG-GPU depends on GDAL, the library that reads and writes geospatial rasters. GDAL is notoriously awkward to install with pip because the Python package has to match a system library exactly. Conda installs both together and keeps them in step, which removes an entire category of problem before it starts.

Install Miniconda — the small distribution — from the Miniconda install page. Anaconda works too, but it is several gigabytes of packages you will not use.

Download the Windows installer and accept the defaults. Do not tick the option to add conda to your PATH — the installer warns against it and it interferes with other software.

Instead, use conda through its own terminal. Open the Start menu and launch Anaconda Prompt. That is the window you will use for every conda and Python command in this course. A normal Command Prompt or PowerShell will report that conda does not exist.

Download the .pkg installer matching your chip — Apple silicon for M1 through M4, Intel for older machines. If you are unsure, check → About This Mac.

Run the installer, then quit Terminal completely and reopen it. Your prompt should now begin with (base), which means conda is active.

Confirm it is there:

You should get something like conda 24.9.2. The exact number does not matter.

05 Build the environment

A conda environment is an isolated set of packages with its own Python. Keeping this project in its own environment means a library upgrade for some other class cannot silently break your model.

Run these one line at a time. The second and third will take several minutes and print a great deal of text — that is normal.

If you have an NVIDIA GPU, add CUDA support as well. Skip this line on a Mac — Apple silicon has no CUDA.

Activate the environment every single time

Your prompt shows which environment is active. If it reads (base) rather than (solweig), none of the packages you just installed are visible, and every import will fail with a confusing message.

Whenever you open a new terminal to work on this project, the first command is always conda activate solweig.

06 Check the install

Three checks, in the shell, with solweig active. Run them in this order.

  • First — the model is installed. It should print a version number.
  • Second — this is the one that matters. It is silent when it works. If it raises No module named '_gdal_array', your GDAL bindings do not match the system library, and the model will fail later in a way that looks unrelated. Fix it now, using the troubleshooting entry below.
  • Third — reports whether a CUDA GPU is available. False is fine and expected on most laptops. The model runs on the CPU; it just takes longer.

09 What goes in

Three rasters describing the shape of the city, plus one meteorological time series. That is the whole input contract.

The rasters

File What it holds
Building_DSM.tif Surface model including roof heights, measured from sea level.
DEM.tif Bare terrain with buildings and vegetation stripped out. Building height is the DSM minus this.
Trees.tif Canopy height. Treated as partly transmissive — casts shade without blocking light completely.
Landcover.tif Optional. Distinguishes albedo and heat capacity by surface material.
All three must be perfectly aligned

Same coordinate system, same resolution, same extent, same pixel grid. If one differs the model refuses to run, and the error message rarely says which file is at fault. Checking alignment before you run is faster than diagnosing it afterwards.

The meteorological forcing

Whichever source you use, the model needs the same variables: 2m air temperature (°C), relative humidity (%), pressure (kPa), and downward shortwave radiation (W/m²). UTCI additionally needs near-surface wind speed (m/s).

That list is not arbitrary. Shortwave feeds the radiation budget; humidity and wind are what turn Tmrt into a comfort index. The inputs follow from the calculation.

Three ways to supply it — a plain text file in UMEP format, ERA-5 reanalysis, or WRF output. Start with the text file. It needs no API keys and no authentication, which makes it the only sensible choice for a first run.

10 Run the sample

The distributed sample covers Austin, Texas on 13 August 2020. The rasters are 3913 × 3367 pixels at 2m resolution — roughly 7.8 × 6.7km, or about 13 million pixels.

Do not run the full domain

Sky view factor over 13 million pixels takes hours on a CPU. And reducing tile_size does not help: tiles are a memory management device, so smaller tiles still compute the whole domain, just in more pieces with more overlap redundancy.

The fix is to cut the raster itself down to about 1km² and run that. One tile at that size finishes in roughly two minutes.

Find somewhere with buildings in it

Cut an empty field and your sky view factor comes out as 1 everywhere, which tells you nothing. Read the raster coarsely first and locate the densest block.

Note the two offsets it prints. If the mean built height comes back near zero, the whole raster may be flat — check that you pointed FOLDER at the right place.

Cut the subset

Put your two offsets into the script below. The critical part is that the same window is applied to all three rasters — if they come out misaligned the model fails immediately.

The guard at the top stops you cutting past the edge of the raster, which would otherwise write files that claim one size and contain another. Beyond that, check two things in the output. All three files should report (500, 500). And Building_DSM's maximum should be meaningfully higher than DEM's — if they are close, you cut a block with no buildings, so go back and pick a different offset.

Copy the meteorological file into place as well, so the run script can find it next to the rasters.

Run it

On macOS the if __name__ == "__main__" guard is not optional

The wall-height step runs in parallel processes. macOS starts those with spawn, which re-imports your script from the top in every child process. Without the guard, thermal_comfort() calls itself recursively and the run dies with BrokenProcessPool. Linux defaults to fork, so the same script works there and hides the problem.

What a healthy run looks like

Two lines are worth reading rather than skipping. The metfile copy succeeding means your selected_date_str matched the date in the meteorological file. And the timezone was inferred from the coordinates — that is what the output bands' timestamps are interpreted against.

Could not find ERA-5 file with roughness length is expected when use_own_met=True. Ignore it.

11 Open it in QGIS

QGIS is a free desktop GIS and it is how you will look at every result from here on.

Install it

Download from qgis.org/download. Take the version marked LTR (long term release) rather than the newest — it is the stable one, and it is what these instructions assume.

Choose the standalone installer for the LTR version, not the OSGeo4W network installer. OSGeo4W is more flexible and considerably more ways to go wrong.

Run it and accept the defaults. It installs several shortcuts; the one you want is plain QGIS Desktop.

Download the .dmg matching your chip and drag QGIS into Applications.

If macOS refuses to open it because the developer cannot be verified, right-click the app icon and choose Open from the menu, then confirm. Doing it that way once registers the exception; double-clicking afterwards works normally.

QGIS is separate from your conda environment

It ships its own Python and its own GDAL. Nothing you installed in step 5 affects it, and nothing you do in QGIS can break the solweig environment. They only ever meet through the files on disk.

Load a result

Open QGIS and drag SVF_0_0.tif from your file browser straight onto the map canvas. Or use Layer → Add Layer → Add Raster Layer if you prefer menus.

Start with SVF, because it is the easiest to sanity-check: it has no time dimension, values run from 0 to 1, and the shape of the streets should be immediately legible.

Make it readable

The default grey stretch is usually poor. Double-click the layer name to open Layer Properties, go to Symbology, and set:

  • Render type → Singleband pseudocolor
  • Band → see the warning below
  • Pick a colour ramp, then press Classify — without this the ramp has no break values and the display stays flat
Bands are timestamps, not colours

Seeing Band 01, Band 02, Band 03 in the layer tree invites you to read them as red, green, blue. They are not. Each band is one timestep of the simulation. QGIS shows Band 01 by default, which is the first hour simulated — and if that is before dawn, your screen goes black and everything looks broken.

For Shadow and Tmrt, switch to a band near midday. Count forward from the first hour in your meteorological file to work out which number that is.

Read actual values

Use the Identify Features tool — the blue i icon in the toolbar — and click a pixel. QGIS prints the value for the band currently displayed. This is how you compare a shaded alley against an open plaza rather than guessing from colour.

Building footprints are empty on purpose

Tmrt maps have holes where buildings stand. SOLWEIG computes the pedestrian-level environment at ground level, so cells occupied by a building have no value. Seeing those holes means the run worked.

What to look at, and in what order

Output How to read it
SVF
Sky view factor		 Look first. A pure form metric with no time in it — 0 is a fully enclosed canyon, 1 is open ground. The urban fabric appears immediately. Computed once and cached, because it is the expensive step.
Shadow Step through the bands and shadows rotate through the day. Night bands are entirely zero.
Tmrt
Mean radiant temperature		 The main result. At midday, identify a shaded alley pixel and an open asphalt pixel — the gap is routinely more than 20°C, in identical air.
UTCI Tmrt blended with temperature, humidity, and wind. Smoother across space than Tmrt, and the more citable figure in a health or policy argument.
Kup / Kdown
Lup / Ldown		 Shortwave and longwave components of the budget. Use them to decompose why Tmrt came out as it did.

The argument this model exists to make fits on a single screen: open the midday Tmrt layer and remember that air temperature is uniform across the whole scene. Twenty degrees of difference, produced by form alone. That is why tree placement and building massing are public health decisions.

12 When it breaks

In roughly the order people hit them.

conda: command not found

Windows: you are in Command Prompt or PowerShell. Use Anaconda Prompt from the Start menu instead.

macOS: the installer finished but your terminal predates it. Quit Terminal completely — not just the window — and reopen. Your prompt should start with (base).

No module named '_gdal_array'

The GDAL Python bindings do not match the system library. This almost always means GDAL arrived through pip at some point. Remove it and reinstall from conda-forge:

pip uninstall gdal
conda install -c conda-forge gdal --force-reinstall

If it persists, deleting the environment and rebuilding is quicker than debugging: conda deactivate, then conda env remove -n solweig, then start step 5 again.

ModuleNotFoundError: No module named 'solweig_gpu'

The environment is not active. Check your prompt — if it says (base), run conda activate solweig and try again. This is the single most frequent cause of "but I already installed it".

zsh: command not found: import

You typed Python at a shell prompt. Either enter Python first with python, or wrap the statement: python -c "import ...".

SyntaxError when running pip install

The reverse — you are inside Python and typed a shell command. Type exit() to leave, then run it at the shell.

Conda hangs for a long time on "Solving environment"

Normal for a first environment with GDAL and PyTorch in it; give it several minutes. If it runs past roughly fifteen, cancel with Ctrl+C and install in two smaller steps — conda install -c conda-forge gdal rasterio first, then conda install -c conda-forge pytorch timezonefinder matplotlib.

torch.cuda.is_available() prints False

Not an error. It means no CUDA GPU was found, which is the normal answer on Macs and on laptops without an NVIDIA card. The model runs on the CPU. Keep your test areas small and you will be fine.

GitHub Desktop: "You do not have permission to push"

You are not a collaborator on the repository yet. Send your GitHub username to your instructor. Cloning and fetching already work, so nothing else this week is blocked.

The terminal says conda is not recognised

You are in a shell that cannot see Miniconda — usually PowerShell inside VS Code on Windows. Run conda init once from Anaconda Prompt and reopen VS Code, or use Anaconda Prompt directly and cd into your folder.

FileNotFoundError or No such file or directory

The terminal is not in the folder you think it is. Run ls (macOS) or dir (Windows) and see whether your script and Input_rasters are in the list. If they are not, you opened a file rather than a folder in VS Code, or you opened the terminal before opening the folder.

BrokenProcessPool, or the opening log prints twice

The macOS spawn problem. Every line that actually runs the model must sit inside if __name__ == "__main__":. See the warning in step 8.

Stuck on "Calculating standalone SVF" for a very long time

Your domain is too large. Stop the run and cut a smaller subset — 500 × 500 pixels finishes in about a minute. Lowering tile_size will not help, because tiles divide the work rather than reduce it.

The run fails immediately, complaining about the rasters

The three subsets are not aligned. Re-run inspect_inputs.py pointed at Input_subset — it must report ALIGNED. The usual cause is applying different windows, or editing one file and not the others.

No metfile copied, or a date-related error

selected_date_str does not match any date in the meteorological file. Open the file, read the first data row, and use that date in YYYY-MM-DD form.

Could not find ERA-5 file with roughness length

Normal when use_own_met=True. Not an error, and nothing is missing.

The QGIS layer is entirely black

You are looking at Band 01, which is probably a night hour. Switch to a band near midday in Layer Properties → Symbology, and press Classify after changing it.

SVF is 1 everywhere

Your subset landed on open ground with no buildings. Pick different offsets — find_dense.py gives you a starting point — and cut again.

The inspection script reports NOT ALIGNED

Print each raster's CRS, resolution, width, and height and compare them by eye — the mismatch is usually one file in a different coordinate system, or a resolution that differs in the last decimal place. If the sample data as distributed reports this, say so rather than trying to fix it; it is worth knowing about.
