01 See the destination

Before touching anything, watch the demonstration of the finished application. Two hours a week for thirteen weeks is a long time to spend without a clear picture of where it ends, and almost every decision in these tutorials makes more sense once you have seen the result.

The application has three moving parts, and you will build them in this order:

  • A frontend — the page in the browser. It shows a map, lets you place components on it, and displays results. Weeks 1 to 6.
  • A backend — a Python program running on a server. It receives your placements and calculates something from them. Weeks 7 to 10.
  • A connection — the frontend sends data to the backend and gets an answer back, as JSON. Weeks 8 and 9.

You do not need to understand how any of that works yet. You will meet each concept again, in context, at the moment you need it. Right now it is enough to know that the thing you are building has three parts and that they talk to each other over the network.

02 Install your tools

Four things, in this order. Take the default options in every installer unless a step below says otherwise.

1 · Visual Studio Code

Download from code.visualstudio.com and run the installer. This is the program you write code in.

2 · Node.js

Download the LTS version from nodejs.org. LTS means "long-term support" — it is the stable one, and the one this course expects. Do not take the version labelled Current.

3 · Python

Download Python 3.11 or later from python.org/downloads.

One checkbox decides your semester

On the first screen of the Python installer, tick Add python.exe to PATH before clicking Install. It is easy to miss and it is off by default. Without it, your computer will not know what the word python means, and you will spend Week 7 fighting your own machine instead of writing code.

4 · Git

Download from git-scm.com/download/win. The installer asks a lot of questions; accept every default. Git is how you save your work and how you hand it in.

1 · Visual Studio Code

Download from code.visualstudio.com, then drag the app into your Applications folder. This is the program you write code in.

2 · Node.js

Download the LTS installer from nodejs.org. LTS means "long-term support" — it is the stable one, and the one this course expects. Do not take the version labelled Current.

3 · Python

macOS ships with an old Python that will not do. Download 3.11 or later from python.org/downloads and run the installer.

On a Mac the command is python3

Throughout this course, wherever a tutorial writes python, type python3 instead. The same applies to pip, which becomes pip3. Plain python on a Mac points at the old system copy.

4 · Git

Open Terminal and run xcode-select --install, then accept the dialog that appears. This installs Git along with the other command line tools. If it reports that the tools are already installed, you are done.

03 Check it worked

Open Visual Studio Code. From the menu bar choose Terminal → New Terminal. A panel appears at the bottom of the window with a blinking cursor. This is the terminal, and you will use it every week from here on.

Type each of these lines and press Enter after each one. Do not type the $ — it just marks where a command starts.

Each line should answer with a version number — something like v22.11.0 or Python 3.12.4. The exact numbers do not matter as long as Node is version 20 or higher and Python is 3.11 or higher.

If any line answers with command not found or is not recognized, that tool did not install correctly. Go to When it breaks below — do not continue past this point with a missing tool.

Take the screenshot now

Capture the terminal with all four answers visible in one image. That screenshot is the first item you hand in this week, and it is easier to take now than to reconstruct later.

04 Create your repository

A repository is a folder whose history is tracked. Yours will hold every file you write this semester, and its address is how you submit work.

Make it on GitHub

Sign in at github.com, creating an account if you need one. Click New repository and set it up like this:

  • Name: spatial-app
  • Visibility: Public or Private - choose based on your preference
  • Tick Add a README file

Create it, then click the pencil icon on README.md and put your name on the first line. Commit that change.

05 Write the HTML

HTML describes what is on a page — not what it looks like. It is made of elements, written as an opening tag, some content, and a closing tag: <h2>Results</h2>. Elements sit inside other elements, and that nesting is the whole structure.

Two attributes matter for this course. class gives an element a label so you can style it later, and id gives it a unique name. Nearly everything below uses class.

Create a file called index.html in your spatial-app folder and paste this in.

Open the file in your browser — right-click it in the VS Code file list and choose Reveal in File Explorer (or Finder), then double-click it. You will see three unstyled blocks stacked on top of each other. That is correct for now. HTML alone has no layout.

Why aside, main, and section instead of div everywhere?

They behave identically. The difference is that their names say what the region is for, which makes the file readable to you in Week 6 and to screen readers always. Use the specific name when one fits.

06 Style it with flexbox

CSS decides how the elements look and where they sit. A rule targets elements by class — .palette means "every element with class="palette"" — and then sets properties on them.

The one layout idea you need

Flexbox arranges children in a row or a column. You set display: flex on a container, and its direct children line up. Two properties do most of the work:

  • flex-direction: row puts children side by side; column stacks them. Row is the default.
  • flex: 1 on a child means "take all the leftover space". flex: none means "stay the size I asked for".

That is the entire mechanism behind the layout you are about to build. The outer .app is a column — top row above, results below. The .top inside it is a row — palette beside map.

Create style.css next to index.html and paste this in. Four values are marked TODO; those are yours to decide.

Reload the page. You should now see a light panel on the left, a large gray area in the middle, and a white strip along the bottom.

Save your work

Refresh your repository page on GitHub. If index.html and style.css are listed there, you are done.

07 When it breaks

These are the failures that actually happen in Week 1. Try the matching answer before searching more widely — general advice on the internet often assumes a different setup than ours.

python is not recognized / command not found

Windows: the PATH checkbox was missed during installation. Re-run the Python installer, choose Modify, and make sure "Add python.exe to PATH" is ticked. Then close the terminal completely and open a new one — an open terminal does not notice PATH changes.

macOS: use python3, not python. This is normal on a Mac and not a problem.

node -v works but npm -v does not

The installation was interrupted partway. Uninstall Node.js from your system settings, restart the computer, and install the LTS version again from scratch.

Git asks for a password and then rejects it

GitHub stopped accepting account passwords over the command line. You need a personal access token instead.

On GitHub go to Settings → Developer settings → Personal access tokens → Tokens (classic), generate a new token with the repo scope, and copy it. When Git asks for a password, paste the token. Save it somewhere private — GitHub will not show it to you again.

The page opens but has no styling at all

The browser could not find style.css. Three things to check: the file is named exactly style.css with no hidden .txt on the end, it sits in the same folder as index.html, and the <link> line in your HTML is inside <head>.

Press F12 to open the browser developer tools and look at the Console tab. A red 404 line naming style.css confirms the file is not where the page is looking.

The palette sits above the map instead of beside it

display: flex is missing from .top, or the palette and map are not both direct children of .top. Flexbox only arranges an element's immediate children — if something is nested one level deeper, it is not part of the row.

Everything is squashed into the top of the window

height: 100vh is missing from .app, so the container is only as tall as its contents. Without a height to divide up, flex: 1 has nothing to distribute.

My changes do not appear when I reload

The file was not saved. VS Code shows a filled dot instead of an × on the tab of any file with unsaved changes. Press Ctrl+S (Cmd+S on a Mac). If it still looks stale, hold Shift while clicking reload to bypass the browser cache.
